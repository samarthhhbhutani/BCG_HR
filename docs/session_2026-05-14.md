## Decisions locked

| Decision | Choice | Reason |
|---|---|---|
| Mount | Sternum SCG, lying down | ~5–10 dB higher SNR than seated finger-press; matches the supine-BCG literature (Inan 2015, Brüser 2013, Paalasmaa 2015). No hand tremor, no postural sway, gravity holds the device. |
| Position | Lower sternum (~halfway between suprasternal notch and the V where ribs split, closer to the V) | Closest chest-wall point to the left ventricular apex — strongest AO peak in SCG. |
| Comm | USB serial @ 921600 baud, binary framed | Lowest latency, most reliable. Tethered is fine for human prototyping. |
| Sample rate | 200 Hz | Comfortable margin above the 25 Hz Nyquist needed for SCG. Higher rates cost battery/storage with no benefit. |
| Accel FS | ±4 g | ±2 g (BCG default) clipped during initial press-down; ±4 g costs 1 bit but eliminates clipping. |
| HR algorithm | Band-pass 5–25 Hz → axis selection by spectral SNR (1–3 Hz vs. 10–30 Hz) → autocorrelation + Hilbert-envelope peak detection, fused | Two-method ensemble; high confidence only when both agree within 8 bpm. ACF is robust to missing beats; envelope catches HR in noisier windows. |
| Window | 8 s, stepped 1 s | ≥2 cardiac cycles for ACF, smooth HR trend without over-smoothing transitions. Standard from Brüser 2011/2013. |
| Validation | Pulse oximeter, hand-compared (no logging) | User reads both numbers and computes deltas mentally. |
| UI | pyqtgraph desktop, 4 panes | Raw axis, filtered SCG, envelope+beats, HR trend. |
| Recording | Manual start/stop via spacebar — app starts in LIVE PREVIEW | Avoids spoiling data with positioning/warm-up garbage. |

## Wire format (22-byte little-endian packets)

| Bytes | Field |
|---|---|
| 0–1 | sync `0xAA 0x55` |
| 2–3 | seq u16 |
| 4–7 | t_us u32 |
| 8–13 | ax, ay, az i16 (FS = ±4 g) |
| 14–19 | gx, gy, gz i16 (FS = ±1000 dps) |
| 20 | CRC8/Dallas over bytes 2–19 |
| 21 | `\n` (eyeball-only, parser ignores) |

Sliding-one-byte resync on CRC failure (so we don't skip a real boundary that happens to follow a bogus sync inside corruption). Drop detection via `(seq - last_seq) & 0xFFFF`.

## Algorithm details (technical deep-dive from the chat)

### Why hardware timer, not `delay()`
`delay(5)` jitters ±1–3 ms because `loop()` time isn't constant. We use `esp_timer_create_periodic(5000)` with an ISR that just sets a `volatile bool tick = true`. Sample interval is hardware-locked.

### Pre-processing chain
1. Detrend (subtract mean — gravity DC).
2. Band-pass 5–25 Hz, 4th-order Butterworth, **SOS form** (numerically stable vs. (b,a)), `sosfiltfilt` (zero phase distortion).
3. Why 5–25 Hz, not 1–20 Hz: sternum SCG energy peaks at the AO/AC valve transients (10–25 Hz), not at the cardiac fundamental. 1–5 Hz is dominated by breathing motion we want to suppress.

### Axis selection — single-axis, NOT PCA
Per window: compute Welch PSD on each raw axis, score by `10·log10(mean P[1–3 Hz] / mean P[10–30 Hz])`, pick highest-SNR axis.

Why not PCA, even though Brüser 2013 uses it:
1. **Sign flips** — eigenvector sign is ambiguous, can flip window-to-window, causing the envelope to invert and the peak detector to miss beats.
2. **Wrong objective** — PCA maximizes total variance, not cardiac-band variance. A breathing-dominated axis can hijack PC1.
3. **Outlier sensitivity** — a single 50 ms motion glitch rotates PC1 by ~20°. Per-axis SNR averages over the spectrum; much more robust.

For sternum-mounted with the screen face flat against skin, `axis=az` typically wins by 5–15 dB. Single-axis is enough for this regime. PCA would help only if cardiac signal split equally across two/three axes (rare with this mount).

If SNR ever caps below ~10 dB consistently, the upgrade path is **fixed-direction projection** onto a unit vector (calibrated from gravity), not PCA — avoids sign flip while still combining axes.

### Method A — autocorrelation
FFT-based ACF: `ifft(fft(x) * conj(fft(x)))` zero-padded to 2n. O(n log n) vs. O(n²) for direct correlation. Search lag range corresponds to 40–200 bpm. Use `scipy.signal.find_peaks` (requires genuine local max), not `argmax` — argmax of a monotone tail returns a false HR.

### Method B — envelope + peak
Hilbert envelope (`|x + j·H{x}|`), 100 ms moving avg, adaptive threshold `mean + 0.5σ`, 250 ms refractory. Median IBI → HR. Median is robust to one missed beat; mean would shift.

### Fusion
- Both methods return a number AND agree within 8 bpm → confident=True, output mean. Green light.
- One method returns a number → confident=False, output that one. Orange light.
- Neither → NaN. Gray.

### Why 8 bpm threshold
Empirical from Brüser 2013. Tighter (5) makes the green light flicker during transitions; looser (15) admits harmonic-confused outputs.

## Architecture / threading

- **Receiver thread**: blocking `serial.read()` → ring buffer + queue.
- **Parquet writer thread**: drains queue → disk. Owns 5-min file rolling. `put_nowait` drops if queue full (so disk lag never blocks ring buffer / live UI).
- **HR worker thread**: every 1 s, pull 8 s window from ring buffer, compute HR.
- **Qt main thread**: 10 Hz QTimer pulls from ring buffer + worker's last `HRUpdate`. Polling, not Qt signals — simpler and fast enough.

## Recording control

App opens in LIVE PREVIEW (UI/HR run, nothing on disk). Spacebar toggles recording on/off. Each "Start" creates `data/session_<UTC>/` containing:
- `session.json` — subject, mount, note, sample rate, full-scale settings.
- `imu_NNNN.parquet` — zstd-compressed, 6 IMU channels + seq + t_us, rolled every 5 minutes.

Multiple separate sessions per app run. Stop = flush + close current; Start again = new directory.

## Test protocol (supine, three trials)

1. Pulse oximeter on left index finger.
2. Lie flat on back, firm surface, no pillow under shoulders, arms at sides.
3. M5Stick screen-down on lower sternum, USB cable trailing toward feet with ~30 cm slack.
4. Wait 10–15 s for green light + `axis=az`, `SNR > 10 dB`.
5. Press Space → start recording.

**Trial 1 — Quiet breathing (60 s):** read M5Stick HR + pulse-ox HR every 15 s. 4 paired readings. Press Space to stop.

**Trial 2 — Breath-hold (30 s):** exhale fully, hold. Press Space to start during breath-hold (or before). Read at 15 s and 25 s. 2 readings. Press Space to stop. (Cleanest possible reading; SNR ≥ 15 dB expected.)

**Trial 3 — Quiet breathing again (60 s):** repeat Trial 1. 4 readings.

Pass criteria:
- Trial 1: 3 of 4 within 5 bpm.
- Trial 2: both within 3 bpm.
- Trial 3: matches Trial 1.

## What blocked the first test run — UNRESOLVED

Built the system end-to-end, smoke tests pass. **Could not actually run a test** because the M5StickC PLUS2's USB connection to the Mac was unstable.

### Symptoms
- M5Stick firmware loaded successfully (screen showed `seq 1578` ticking).
- Port `/dev/cu.usbserial-5B1E0428731` enumerated intermittently.
- Probed presence over 15-second windows, observed:
  - 1/15 PRESENT (mostly gone)
  - 0/15 PRESENT (gone entirely)
  - Mid-read failures: `[Errno 6] Device not configured`
  - `Got 440 bytes` at 921600 once, but bytes contained no `0xAA 0x55` syncs — suggests a baud mismatch transient or corruption.

### Diagnosis
Physical USB-C link is marginal or dead. Three candidates ranked by likelihood:
1. **Cable** (~70%) — charge-only or marginal data cable. Power flows (screen lights), data doesn't.
2. **Hub/dongle in the path** (~15%).
3. **M5Stick USB-C connector lint or damage** (~10%).

Did NOT attempt: cable swap to a known-good data cable, direct-to-Mac (no hub), different Mac port.

### Resolution path (next session)
1. Use a known-good data cable (came with a phone/SSD/laptop, not a charger).
2. Plug directly into the Mac.
3. Verify with: `ls /dev/cu.usbserial-* 2>/dev/null && echo PRESENT || echo GONE` — run 3 times, 5 s apart, all 3 should print PRESENT.
4. Read sanity check at 921600: `python -c "import serial; s=serial.Serial('/dev/cu.usbserial-5B1E0428731',921600,timeout=2); d=s.read(440); print(len(d), [i for i in range(len(d)-1) if d[i]==0xAA and d[i+1]==0x55][:5])"` — should report 440 bytes with regular `0xAA 0x55` syncs at ~22-byte intervals.
5. Then run the app and proceed to the test protocol.
