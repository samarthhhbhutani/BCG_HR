## Diagnosis of the live HR error

Replayed `hr_worker.py` over the recorded `session_20260516T050032Z` Parquet:

| metric | live algorithm | oximeter |
|---|---|---|
| fused HR (median) | **108 bpm** | 63–75 |
| envelope-only (median) | 121 bpm | — |
| ACF-only (median) | 74 bpm | — |
| selected axis distribution | ax 5×, ay 5×, az 1× | — |

ACF-on-az is approximately right; everything else is wrong because:

1. **Axis selection thrashes.** Per-window, per-axis SNR (1–3 Hz / 10–30 Hz) on an 8 s segment is too noisy — it picked ax or ay 11/12 windows even though az has 12.6 dB cardiac SNR vs. 8.2 dB for ay across the full 75 s session. When ax/ay get picked, ACF locks onto noise harmonics or the second harmonic of cardiac.
2. **Envelope harmonic doubling.** Hilbert envelope of a sharp S1/S2 burst pair has strong 2× content; with `HR_MAX = 200` the search admits ~130 bpm freely.
3. The 8 s window has no continuity guarantee — axis can flip every step, so the displayed HR jumps between f, 2f, and noise.

---

## Decision: switch to PCA-based axis fusion

Per current literature for **wearable / chest-mounted SCG**, single-axis-by-SNR is the earliest method (Brüser 2011, Pandia 2012). Modern default is PCA on the band-passed tri-axis signal — projects the cardiac vector onto its dominant direction regardless of how the device sits.

Recipe:
1. Band-pass each axis 5–25 Hz (existing chain).
2. Stack N×3, run SVD.
3. PC1 = projection of cardiac vector with maximum in-band variance.
4. Run ACF + envelope HR on PC1 (instead of one raw axis).

Why this is fine to do here even though the 2026-05-14 log argued *against* PCA:
- The "PCA gets hijacked by breathing" concern is moot because we **band-pass before** SVD — breathing energy (0.2–0.4 Hz) is already removed when SVD runs. PC1 maximizes variance only inside the cardiac band.
- Sign flip doesn't matter because both HR methods are sign-invariant: ACF is sign-symmetric; Hilbert envelope is `|·|`.
- The "outlier sensitivity" concern is real but small at the resting-supine SNR levels we're seeing (≥ 8 dB on the worst axis); add motion gating later if it becomes an issue when we move to ambulatory dog recordings.

If PCA proves brittle, the fallback path is the same as before: **fixed-direction projection** onto a unit vector calibrated from gravity (still combines axes, no sign flip).

## Previous axis-selection code (preserved here for switch-back)

The old `_select_axis` is commented out in `hr_worker.py:65–82` rather than deleted. For convenience it's reproduced here verbatim — to revert, uncomment in place and call from `_process`.

```python
def _select_axis(window: np.ndarray, fs: float) -> tuple[int, float]:
    """Return (col_index_in_window, snr_db). Picks axis with most 1-3 Hz energy."""
    best_col, best_snr = 0, -np.inf
    for col in range(3):
        x = window[:, col] - np.mean(window[:, col])
        f, p = welch(x, fs=fs, nperseg=min(len(x), 1024))
        cardiac = (f >= 1.0) & (f <= 3.0)
        noise = (f >= 10.0) & (f <= 30.0)
        if not cardiac.any() or not noise.any():
            continue
        sig = float(np.mean(p[cardiac]))
        nse = float(np.mean(p[noise])) + 1e-12
        snr = 10.0 * np.log10(sig / nse)
        if snr > best_snr:
            best_snr = snr
            best_col = col
    return best_col, float(best_snr)
```
